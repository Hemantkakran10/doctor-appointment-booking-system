2. Database Collection Schemas

User Schema (Patients & Admins)

Stores patient details and administrator accounts. Includes automatic Bcrypt encryption pre-save hooks.

const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true, lowercase: true },
  password: { type: String, required: true, select: false },
  role: { type: String, enum: ['Patient', 'Admin'], default: 'Patient' },
  phone: { type: String, required: true }
}, { timestamps: true });

Doctor Schema

Stores practitioner details, specialization badges, and booking matrixes.

const doctorSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  password: { type: String, required: true, select: false },
  specialization: { type: String, required: true },
  degree: { type: String, required: true },
  experience: { type: Number, required: true },
  fees: { type: Number, required: true },
  slots_booked: { type: Map, of: [String], default: {} }, // Key is YYYY-MM-DD
  isActive: { type: Boolean, default: true },
  role: { type: String, default: 'Doctor' }
}, { timestamps: true });

Appointment Schema

Stores transactional booking references linking Patients and Doctors.

const appointmentSchema = new mongoose.Schema({
  userId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  docId: { type: mongoose.Schema.Types.ObjectId, ref: 'Doctor', required: true },
  slotDate: { type: String, required: true }, // YYYY-MM-DD
  slotTime: { type: String, required: true }, // HH:MM AM/PM
  amount: { type: Number, required: true },
  cancelled: { type: Boolean, default: false },
  isCompleted: { type: Boolean, default: false }
}, { timestamps: true });

3. Double-Booking Validation Logic

To protect the database from double-bookings, the system inspects the doctor's slots_booked Map before registering the appointment transaction. If the time is available, it appends the hour to that date and saves the doctor. Upon cancellation, it filters out the hour, releasing the slot. 

// In backend/controllers/appointmentController.js
const bookedSlots = doctor.slots_booked.get(slotDate) || [];

// Check double-booking
if (bookedSlots.includes(slotTime)) {
  return res.status(400).json({ message: 'This time slot is already booked' });
}

// Proceed to book
const appointment = await Appointment.create({ userId: req.user._id, docId, slotDate, slotTime, amount: doctor.fees });
bookedSlots.push(slotTime);
doctor.slots_booked.set(slotDate, bookedSlots);
await doctor.save();

4. Secure Authorization Middleware

The system verifies clients using a Bearer token. Once verified, the credentials can be restricted using a curry filter matching specific role constraints: 

// In backend/middleware/authMiddleware.js
export const restrictTo = (...roles) => {
  return (req, res, next) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(403).json({
        message: `Access denied. Role '${req.user ? req.user.role : 'None'}' is unauthorized.`
      });
    }
    next();
  };
};

6. Generative AI & Clinical LLM Suite

ArogyaCare integrates state-of-the-art Generative AI and Multimodal Computer Vision:

  • Intelligent Symptom Analysis: Natural language symptom input with automated clinical triage categorization (Urgent, Moderate, Mild), differential condition consideration, and AI-driven doctor matching.
  • AI-Driven Doctor Recommendations: Dynamically scores and recommends verified clinic network practitioners matching identified medical specializations with 1-click slot booking.
  • 24/7 Conversational Medical Chatbot: Persistent floating AI health assistant for patient inquiries, doctor specialty guidance, appointment booking assistance, and clinical preparation advice.
  • Advanced Multimodal OCR Technology: Decodes handwritten and printed doctor prescriptions (translates Latin abbreviations like OD, BD, TDS, PC, HS into plain language) and analyzes laboratory diagnostic reports (CBC, Lipid profile, Metabolic panel) with biomarker reference range evaluation, abnormal value highlighting, and specialist consultation links.

7. Front-End Context Architecture

The Client UI uses React Context providers to handle auth states and global triggers:

  • AppContext: Stores global loading flags (toggles backdrop overlays) and manages fading dialog messages.
  • AuthContext: Caches JWT signatures, runs startup handshakes to restore profiles on boot, and redirects users to role dashboards after validation.
  • ThemeContext: Manages light and full-site dark mode themes, persisting preferences in local storage.
